# Partner notifications
Existing authenticated notification APIs and Firebase device registration are unchanged. New partner worker observes committed MongoDB changes; requires Atlas/replica set. Run one backend worker instance for best checkpoint consistency. Existing direct approval/rejection notifications remain. The worker uses recipient-scoped event keys; updateLookup can coalesce rapid updates, and assignment history is best-effort cached. No historical backfill. Reminders run every minute for approved visits and property/profile promotions. Low balance alerts use the wallet threshold and crossing only. No automatic WhatsApp messages.

Implemented rules: registration/application submission/review, KYC resubmission, account block/unblock, profile/password changes, team membership and allocation, property assignment/delegation/status/price/details/removal, successful wallet transactions and recorded failed payments, lead assignment/allocation/status, refund request status, promotion submission/cancellation, visit creation/team outcomes, expiry and visit reminders. Existing direct triggers preserved; repeated KYC correction key now includes updatedAt.

Not implemented: separate seller assignment without a schema field, insufficient-balance attempts, separate follow-up scheduling, weekly/monthly reports, pending request reminders, credit offers/price announcements, buyer feedback, durable FCM retry/delivery tracking. Promotion renewal uses new request flow. Existing push delivery is best effort. Live MongoDB/FCM testing required. Test with a registered partner device and verify notification list and push. No new frontend routes required.
