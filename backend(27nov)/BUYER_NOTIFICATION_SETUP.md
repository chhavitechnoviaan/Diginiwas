# Buyer notifications
Existing notification API and Firebase FCM are reused. Configure existing Firebase credentials, register device token using authenticated buyer account. MongoDB replica set / Atlas required for change streams. Worker starts at deployment, not historical backfill. Reminder scan every minute; event keys deduplicate per recipient. Existing visit outcome controller handles approval/rejection/cancellation/completion/rescheduling, including repeat reschedule and team rejection fixes. Loan confirmation requires buyer Bearer token; anonymous enquiries still work without push.
Saved property updates use SavedProperty.buyerId and propertyId. Price alerts show current price only (no reliable previous price in change stream). Account email verification, new device login, matching preferences, marketing offers, loan lifecycle, support replies and feedback require additional business functionality. Push retry and delivery tracking not added. Live MongoDB and FCM testing required. Change streams use updateLookup, not exact historical post-images; rapid updates may coalesce. Existing workers unchanged.
