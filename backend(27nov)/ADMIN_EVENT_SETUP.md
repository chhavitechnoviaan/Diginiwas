# Admin notifications extension
Existing in-app notifications, FCM and branded SMTP emails are preserved. The new worker observes committed MongoDB inserts/updates, stores a resume checkpoint and uses event keys for per-admin notification and shared inbox email deduplication. MongoDB replica set or Atlas is REQUIRED for change streams (standalone MongoDB will not work). Start the backend with the existing environment, including MONGO_URI, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, ADMIN_NOTIFICATION_EMAIL=diginiwas@gmail.com. No WhatsApp API credentials are needed. Existing email WhatsApp support link is unchanged.

Events: buyer/seller record creation; partner approval/rejection, identity document changes and sub-partner creation; property submission, assignment/review, verified/rejected/live/sold/rented/inactive across all five property collections; promotion and profile boost approved/rejected/expired; successful credit purchase/debit/refund, recorded payment failure, low balance threshold crossing; lead refund review; visit approval/rejection/cancellation/completion; support query creation. Low balance uses the existing wallet threshold (100 single / 500 team fallback). Payment failure requires the existing payment flow to persist FAILED. Abandoned payments without a recorded failure are not detected. Expiry alerts run every minute for approved requests reaching their expiry after deployment; the existing maintenance endpoint still manages actual expiration status. Historical records are not backfilled. Change streams require oplog retention sufficient for downtime; if a resume token becomes invalid, an operator must investigate before resetting the checkpoint (resetting skips missed history). Update lookup can return a newer document; event status is read from updatedFields where available. Replacement writes are not observed. Existing registration notifications are preserved; buyer/seller creation can precede OTP verification.

Support: new authenticated POST /api/v1/support-queries with JSON {"subject":"Help","message":"Please assist"}. Returns 201 with data.id. Existing uploaded project has no support submission screen; mobile/web client must call this endpoint. Admin can read the subject/message in Notifications. No automatic WhatsApp sending.

Frontend: updated category tabs, 30-second refresh and bell polling. Filters/search are page-local as before. Existing API and read/unread endpoints unchanged.

Validation: node --test tests/adminEventRules.test.js; node --check on changed backend modules. Live MongoDB/SMTP/FCM and frontend build require installed dependencies and configured environment. Test each event with a real staging account and check notifications, notificationdeliveries and admin_event_checkpoints collections. Email provider acceptance is not inbox delivery confirmation. Do not commit .env or service account secrets.
