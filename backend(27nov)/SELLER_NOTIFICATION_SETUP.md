# Seller notifications
Existing Admin and Partner notifications are unchanged. Seller events are observed via MongoDB change streams (Atlas/replica set required), with persisted resume checkpoints. Start backend normally. Firebase credentials and registered Seller device tokens are required for push. In-app persistence works without FCM tokens. Existing push delivery is best effort, no automatic retry. No Seller email or WhatsApp sending added.

Coverage: account registration, email/mobile verification, application/account status, password/profile updates; property status, verification, assignment, price/details, deletion (owner cache), partner blocked/deleted/suspended; boost submission, existing approvals/rejections, cancellation, 3-day/1-day/expiry alerts; lead creation/status; visit request/approval/status and 24h/1h reminders; weekly enquiry/visit counts and no-enquiry alerts. Notifications are generated only for actual persisted fields. Profile/price updates are not actor-specific. Renewal is not a distinct workflow; a new request uses existing submission/approval events. No view milestone, listing expiry, or dedicated buyer feedback event is added because corresponding reliable source fields/workflows have not been established. No distinct KYC or password-reset event beyond password update. Hard deletion requires cached owner. Change streams use updateLookup, not historical preimages; rapid successive updates can affect contextual fields. Reminders run every minute; weekly scan hourly, first summary may be immediate. Existing notifications do not backfill. Live integration testing required.
